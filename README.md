# Life Manager

시간 기록을 삶의 목표와 연결하는 아이폰·PC용 웹앱입니다. [weekly-time-budget](https://github.com/LionDaniel79/weekly-time-budget)의 시간 기록, 타이머, 일간·주간 예산, 성장·절제 점수와 다섯 통계를 이어받았습니다.

## 로컬 실행

`app-start.cmd`를 두 번 클릭합니다. 또는 `npm ci` 후 `npm start`를 실행하고 http://127.0.0.1:4173 을 엽니다. Node.js 22 이상이 필요하며 실행 창을 열어 두어야 합니다.

## 메뉴

- 대시보드: 선택한 목표, 일간·주간 예산 진행과 점수.
- 시간기록: 타이머·일시정지·카운트다운, 분 수동 입력, 최근 기록, 여러 목표가 겹치는 기록의 배정.
- 시간예산: 일간·주간 시간 예산 설정.
- 목표설정: 생애·장기·중기·단기 목표와 활동 연결, 시간·숫자·매일 기준, 단기 기간 반복, 대시보드 표시와 순서, 보관과 삭제.
- 통계: 주별·월간·연간·월간 비교·연도별 비교·목표통계. 목표 진행은 마지막 목표통계 버튼에서 봅니다.
- 앱 설정: 항목 생성·수정·보관·삭제·순서, 목표 데이터 백업·복원, 전체 자료 내보내기.

## 숫자 목표와 보관·삭제

목표는 이름·진행 수치·막대·동작 버튼이 가로로 이어지는 행으로 표시합니다. 대시보드·목표설정·목표통계에 동일하게 적용하며, 좁은 화면에서는 필요한 부분만 다음 줄로 배치합니다.

중기 목표 등에서 시작값·목표값·단위를 설정하고 카드의 **현재값 기록**으로 실측값을 입력합니다. 체중 80→70kg, 현재 75kg이면 50%이며 횟수 0→5회, 현재 3회이면 60%입니다. 현재값은 합산하지 않습니다. 목표값 0도 가능하며 시작값과 목표값은 달라야 합니다. 측정 전에는 미측정으로 표시하고, 달성률이 100%를 넘어도 자동 완료하지 않습니다. 단위 변경 전 기록은 별도 이력으로 남습니다.

목표 상세의 **보관**을 누르면 대시보드·목표통계와 기본 목록에서 숨겨지고, 목표설정 아래 접힌 **보관 목표** 영역으로 이동합니다. **보관 해제·수정**에서 상태와 연결을 다시 설정해 복원합니다. **목표 삭제**는 확인 후 해당 목표를 목록에서 제거하며, 원본 시간 기록과 하위 목표는 유지합니다. 과거 집계를 위해 삭제 날짜와 연결 이력은 내부 자료에 보존합니다.

보관·삭제하는 날 이미 입력한 시간도 당시 상위 목표에 남고, 이후 새 기록은 종료된 연결에 누적되지 않습니다. 시간기록의 **목표별 시간 배정**에서 보존된 배정을 바꾸거나 해제할 수 있습니다. 원본 기록의 분·날짜·항목 정정과 삭제는 집계에 반영됩니다.

## 단기 목표 반복과 하위 연결

단기 목표에서 시작일·종료일을 지정하고 **설정한 기간으로 반복**을 켭니다. 양 끝 날짜를 포함한 길이로 반복합니다. 9월 1~15일은 15일이므로 9월 16~30일, 10월 1~15일로 이어집니다. 월별 반복이 아니므로 달의 길이에 맞춰 바뀌지 않습니다. 며칠 뒤 앱을 열어도 현재 기간을 바로 표시합니다.

카드에는 현재 기간의 시간·숫자 진척을 표시하고, 상세의 **반복 기간별 기록**에서 최근 12개 기간을 확인합니다. 숫자 목표는 기간마다 새 현재값을 기록하며, 시간 목표를 비워도 기간별 시간을 볼 수 있습니다. 원본 기록은 유지하고 상위 목표에는 기간을 넘어 계속 누적합니다. 잠시 멈춤·완료·보관 상태에서는 기간 전환을 멈춥니다. 반복을 끄면 편집 화면에 지정된 시작일·종료일의 일반 목표가 됩니다.

장기 목표의 하위 선택은 **하위 중기 목표 / 하위 단기 목표**, 중기 목표는 **하위 단기 목표 / 기본 항목 (시간 기록)**으로 구분합니다. 단기 목표는 중기 또는 장기에 직접 연결할 수 있으며 상위 목표는 하나입니다. 다른 상위에 있던 목표를 선택하면 적용일부터 연결을 옮기고 이전 기록은 당시 상위 경로에 남습니다.

## 데이터

같은 Google 계정으로 기존 시간 예산 앱의 시간·예산·항목을 그대로 사용합니다. **이 앱에서 실제 시간 기록과 예산을 수정하면 기존 앱에도 반영됩니다.** 자동 검증은 실제 계정 대신 합성 자료를 사용합니다.
목표 데이터는 `users/{uid}/lifeManager/state`에 별도로 저장됩니다. 이전 독립 체중·점검 기록은 화면에서 제외하지만 기존 백업과 저장 자료에는 보존합니다. 원본 시간 기록은 복제하지 않고 기록일에 적용되는 목표 연결로 집계합니다. 상위 합산 시 중복 계산하지 않습니다. 여러 중기·단기 목표가 겹치면 시간기록 메뉴에서 직접 배정하며, 이전 배정이 유효하지 않게 되면 다시 선택할 수 있습니다.

시간 목표가 없으면 누적만 표시합니다. 하위 목표로 상위 목표의 분모를 자동 생성하지 않습니다. 시간 달성이 결과 완료를 뜻하지 않으며, 결과값은 현재 전체 값을 직접 갱신합니다.

중기·단기 목표 모두 **수정·연결 → 기본 항목 (시간 기록)**에서 항목을 선택할 수 있습니다. 중기 목표는 하위 단기 목표도 함께 연결할 수 있습니다. 동일 항목에 연결된 목표가 여러 개면 **시간기록 → 목표별 시간 배정**에서 하나를 선택합니다. 단기 목표에 배정한 시간은 연결된 중기·장기 목표에도 한 번씩 반영됩니다. 중기 목표에 직접 배정한 시간은 그 하위 단기 목표에는 반영되지 않습니다.

주별·월간·연간 통계의 항목별 달성률은 가로 막대와 작은 비율 숫자로 표시합니다. 성장 목표의 100% 초과 달성은 꽉 찬 막대에 실제 비율을 표시하고, 절제 목표의 음수 달성률은 초과분의 크기를 붉은 줄무늬로 표시합니다. 예산이 없는 항목에는 막대 대신 계산 제외를 표시합니다.

시간 기록은 기존 오프라인 저장과 재전송을 유지합니다. 목표 변경은 온라인 서버 저장을 확인합니다. 오프라인에서는 마지막 목표를 읽을 수 있습니다. 다른 기기의 변경을 덮어쓰지 않도록 revision을 비교합니다. 목표 문서가 800 KB를 넘으면 기존 자료를 보존하고 저장 구조 확장을 안내합니다.

사용 이력이 있는 항목은 보관합니다. 목표 백업 복원은 목표 자료와 보존된 이전 부가 기록을 교체하고 시간·예산은 유지합니다. 전체 내보내기는 보관용이며 전체 가져오기는 없습니다.

## 검증과 배포

`npm test`, `npx playwright install chromium webkit`, `npm run test:browser`, `npm run build` 순서로 검증합니다.
`_site/`에는 공개 앱 자산만 들어갑니다. 개인 기획·분석·시안은 `local-data/`와 `analysis/`에 보관하며 Git에서 제외합니다. 기존 로컬 첫 버전의 `archive/local-prototype-v1` 브랜치는 공개하지 않습니다. **git push --all을 사용하지 마세요.**

`upstream`은 원본 저장소, `origin`은 life_manager입니다. GitHub의 정식 fork 표시와는 별도로 원본 이력을 가져온 파생 개발 공간입니다. 기존 운영 앱을 유지하고 새 Pages 경로에 배포합니다. Pages 배포 소스는 GitHub Actions로 설정합니다.
Firebase 설정은 기존 운영 웹앱의 공개 클라이언트 설정입니다. 관리자 비밀키가 아니며 실제 접근은 로그인과 firestore.rules로 제한됩니다. GitHub의 FIREBASE_* 변수로 교체할 수 있습니다.

진행 상태: [개발 인계](docs/DEVELOPMENT_HANDOFF.md). 구현 근거: [통합 계획](docs/UPSTREAM_INTEGRATION.md).

## 운영과 복구

Life Manager의 설치 식별값은 `/life_manager/`입니다. 기존 시간예산 앱과 각각 설치할 수 있도록 분리했습니다. 이전 버전은 두 앱의 식별값이 같아 Chrome이 이미 설치한 앱으로 인식할 수 있었습니다. 기존 설치를 자동 제거하지 않으며, 새 식별값으로 설치하면 예전 아이콘이 함께 남을 수 있습니다. 설치 시 앱 주소가 `/life_manager/`인지 확인하세요. 접속 주소와 로그인·데이터 저장소는 동일하게 유지됩니다.

PC Chrome에서는 현재 운영 주소를 열고 **⋮ → 전송, 저장 및 공유 → 페이지를 앱으로 설치**를 사용합니다. 설치된 앱은 `chrome://apps`에서 확인할 수 있습니다. 이미 Life Manager를 새 식별값으로 설치했다면 **앱 열기** 표시가 정상입니다. 오래된 아이콘을 정리할 때는 기록 보존을 위해 **Chrome에서도 데이터 삭제**를 선택하지 마세요.

배포 주소: https://liondaniel79.github.io/life_manager/ . 기존 운영 주소 https://liondaniel79.github.io/weekly-time-budget/ 는 유지합니다. main에 검증한 변경을 올리면 GitHub Pages에 자동 배포됩니다. 개발은 feature/upstream-goals 같은 별도 브랜치에서 진행합니다. 실패하면 GitHub Actions의 실패 단계와 로그를 확인하고, 문제 커밋을 git revert로 되돌려 다시 배포합니다.

Firebase 승인 도메인은 liondaniel79.github.io 입니다. 로컬 로그인에 필요한 경우 localhost와 127.0.0.1도 Firebase Authentication 설정에서 승인해야 합니다. 새 프로젝트를 만들 때 Google 공급자와 firestore.rules를 적용하세요. 현재 연결은 기존 프로젝트를 사용합니다.

설정 교체 변수: FIREBASE_API_KEY, FIREBASE_AUTH_DOMAIN, FIREBASE_PROJECT_ID, FIREBASE_STORAGE_BUCKET, FIREBASE_MESSAGING_SENDER_ID, FIREBASE_APP_ID. FIREBASE_MEASUREMENT_ID는 선택 항목입니다. Firebase Spark 무료 한도에서 시작하며 이번 작업은 결제 계정을 새로 연결하지 않습니다.
